# colorful-body

Claude の応答本文を、Markdown ビューアの [glow](https://github.com/charmbracelet/glow) のような見た目で描く。
見出し・インラインコード・箇条書き・表に色が付き、どこが見出しでどこがコードかがひと目で分かる。
あなたの発言は、右寄せの枠で囲んで描くので、Claude の返答と見分けやすい。

## 描き方

| 要素 | 標準 | colorful-body |
| --- | --- | --- |
| `#` 見出し | 太字・斜体・下線 | 黄文字・青紫背景のバッジ |
| `##` 以降の見出し | 太字 | 見出しの記号（`##`）を付けた青い太字 |
| インラインコード | 薄紫 | 赤字・灰背景（前後に空白を足す） |
| 箇条書き | `-` | `•`（入れ子はインデントで揃え、折り返した行も本文の位置に揃える） |
| 表 | 罫線の箱 | ヘッダの下に `─┼─`、列の間に `│`。全角文字は幅 2 で数え、狭いときは列を縮めてセル内で折り返す |
| 見出し・段落・リスト・表の境目 | そのまま | 空行を 1 つ入れる |
| 返答の先頭 | `●` | 自前で `●` を描き足す |
| あなたの発言 | `❯` 付きで、背景色が画面の幅いっぱいに付く | 右寄せの角の丸い枠（枠は青紫、背景は暗い紫）。幅は文章に合わせ、画面の 80% を超えたら折り返す |
| URL・`[ラベル](URL)`・パスらしいインラインコード（`links` をオンにしたとき） | 文字のまま | 下線付きのリンク（OSC 8 のハイパーリンク）。[リンク](#リンク)を参照 |

色は glow の dark スタイルに目で合わせた値（xterm-256 の 228・63・39・203・236 に近い色）。変えるときは `hooks/register.tsx` 冒頭の定数を書き換える。

## 標準の描画に任せるもの

次は、作り直さずにエンジン標準の描画のままにする。

- コードフェンス（` ``` `）
- 引用（`>`）
- リストの続きの行（インデントだけで始まる行）
- 要約として描かれる行（`isSummary`）
- あなた以外の発言（バックグラウンドタスクの通知、ほかのエージェントやセッションからのメッセージ）。枠で囲むのは、ターミナルで入力した発言（`origin.kind` が `composer`）だけ

## リンク

設定 `links` をオンにすると、次をリンクにする。**既定はオフ。**

- 本文の `https://…` や `http://…`（末尾の `.` `,` `)` などは含めない。全角文字の手前で止める）
- `[ラベル](https://…)` 形式（ラベルをリンクの文字にする）
- インラインコードの中身が URL のとき
- インラインコードの中身がパスらしいとき: `~/…`、`/a/b…`（2 階層以上）、`./…`、`../…`、拡張子のある `a/b.ts`。パスは `file://` に直し、`~` と相対パスは `HOME` と作業ディレクトリで絶対パスにする。末尾の `:行` や `:行:桁` は外してリンク先にする

`/compact` のようなスラッシュコマンドや、`a/b` のように拡張子のない相対パスはリンクにしない。コードフェンスの中と引用の中も対象外。

オフが既定なのは、端末が OSC 8 に対応していないと、読みづらくなるため。Claude Code は、端末の OSC 8 対応を検出できないと、リンクの文字のあとに URL を足して描く。このとき URL が二重に出て、パスは長い `file://` が付く。クリックしても何も開かない。環境変数 `FORCE_HYPERLINK=1` で OSC 8 を強制できるが、端末が実際に対応していないと意味がない。

クリックしたときに何が開くかは、端末が決める（多くの端末では Cmd+クリックか Ctrl+クリック）。使う前に、まず 1 つの URL で、一重に下線だけが付くことと、クリックで開くことを確かめるとよい。

## 設定

`/config` の colorful-body の欄で変えられる。

| 項目 | 内容 | 既定 |
| --- | --- | --- |
| `frame` | あなたの発言を、右寄せの枠で囲んで描く。オフでは標準の描画 | オン |
| `links` | URL とパスをリンクにする（OSC 8 に対応した端末向け。[リンク](#リンク)を参照）。オフでは、リンクにせず文字のまま描く | オフ |

## この mod がすること・しないこと

すること:

- フックするイベントは 1 つ: `ui.render`。対象は 2 つの描画で、応答の本文（`AssistantMessage`）と、あなたの発言（`UserMessage`）。本文は行ごとに分け、見出し・段落・リスト・表は自前の木で描き、それ以外は標準の `Markdown` 要素に渡す。発言は 1 つの枠の木で描く
- 使うエンジンの機能: `$.ui.resolve`（描画に使う要素の表）、`$.env.get`（環境変数 `HOME` だけ。`~` を絶対パスにするため）、`$.session.cwd`（作業ディレクトリ。相対パスを絶対パスにするため）

しないこと:

- ツールの呼び出しや会話の内容を止めたり、書き換えたりしない（描画だけを差し替える）
- 通信しない。ファイルを読み書きしない。コマンドを実行しない
- 本文やパスを保存・送信しない。パスが実在するかは確かめない（リンクにするだけで、開かない）

`claude plugin validate colorful-body` を実行すると、フックするイベントと呼ぶ機能を確かめられる。

## 既知の制限

- `#` 見出しのバッジは 1 行向け。長い見出しは、背景色つきで折り返して読みにくくなる
- 表の幅は、全角と絵文字を幅 2、そのほかを幅 1 として数える。端末がこれと違う幅で描くと、罫線が数桁ずれる
- 太字とインラインコードは、行の中で閉じているものだけを解釈する。行をまたぐものは文字のまま出る
- 枠の幅は、全角を 2、そのほかを 1 として数える。端末の幅の数え方が違うと、右の枠が数桁ずれる
- `ctrl+o` で全文を出したときの枠は確かめていない
- ターミナル以外の画面（デスクトップなど）では確かめていない
- リンクは、herdr 越しでは OSC 8 が検出されず、代替表示（URL が二重に出る）になることを確かめた。`FORCE_HYPERLINK=1` でクリックが通るかは確かめていない
- パスの判定は文字の形だけで行う。拡張子のあるものは、存在しなくてもリンクになる

## 開発

```bash
claude plugin validate colorful-body
claude plugin test colorful-body
npm run typecheck   # リポジトリ直下で実行する
```
